# Ejercicio 4 - Guia  3

Se desea implementar un monitor Atrapador que permite coordinar varios threads.
Un atrapador provee dos operaciones esperar() y liberar(N). La idea es que cada uno de los threads puede invocar a cualquiera de las operaciones: un thread que invoca a esperar se deberá bloquear hasta tanto sea liberado por algún otro thread que invoca a la operación liberar(N). El parámetro N indica cuántos threads de los que están bloqueados deberán liberarse.

a) Dar una solución en la que el thread que invoca liberar(N) nunca se bloquea. Además sólo se liberan threads si hay N o más threads esperando. En el caso en que haya menos de N threads, ninguno se liberará y deberán continuar esperando. En su soliución, ¿Es posible que un thread que no esperó pase directamente y deje esperando a un thread que ya hab´ıa esperado? ¿Cómo lo solucionar´ıa?

b) Modificar la solución anterior para hacer que en el caso en que haya menos de N threads esperando, el proceso que invoca a liberar se bloquee hasta tanto se puedan liberar N threads (todos los threads que esperan se deben liberar juntos).

## Punto a

``` java
monitor Atrapador {
  int turnera = 0;
  int turnoActual = 0;
  int esperando = 0;
  conditional free;

  public void esperar(){  
    int miTurno = turnera;
    turnera++;
    esperando++;

    while(miTurno > turnoActual){
      free.wait();
    }
  }

  public void liberar(int N){
    if(esperando >= N){
      turnoActual += N;
      esperando -= N;
      free.signal(N);
    }
  }
}
```
